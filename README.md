# speedtest — замер скорости интернета

Делает 10 последовательных запросов к файлу, дожидается ответа каждого,
считает среднее время, объём скачанных данных и печатает скорость в МБ/с
вместе с математическим ожиданием и стандартным отклонением.

Асинхронный: `asyncio` + `httpx`. Вывод в консоль — `rich`.

## Запуск

### Docker

```bash
docker compose run --rm speedtest
```

Полный прогон качает **1 ГБ** трафика (10 запросов по 100 МБ). Свой адрес:

```bash
docker compose run --rm speedtest https://ash-speed.hetzner.com/1GB.bin
```

### Локально

Python 3.11+.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

python app/main.py                        # дефолтный адрес
python app/main.py https://host/file.zip  # свой адрес
```

Адрес, число запросов и таймаут задаются константами в начале `app/main.py`:
`URL`, `REQUESTS`, `TIMEOUT`.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest -q
```

Сеть замокана заглушкой, сокеты не трогаются. Тесты параметризованы и
помечены маркером `unit` — прогнать только их: `pytest -m unit`.

## Файлы

| Файл | Что делает |
|---|---|
| `app/main.py` | настройки замера, httpx-клиент, вывод через rich |
| `app/core.py` | `download()` — один запрос; `measure()` — цикл замеров; `stats()` — математика |

Одна функция — одна работа: `core.py` не знает про консоль, `main.py` не
считает статистику и не читает тело ответа.

## Что и почему так считается

**Среднее время запроса** — `M(ξ)` по всем запросам; **стандартное отклонение**
`s(ξ)` — с поправкой Бесселя (делится на `n−1`): десять запросов — выборка
поведения канала, а не вся совокупность, и деление на `n` занизило бы оценку.
При одном замере разброс нулевой, чтобы не делить на ноль.

**Средняя скорость** — все байты, делённые на общее время. `M(ξ)` и `s(ξ)`
скорости считаются по каждому запросу отдельно.

**Байты считаются при чтении тела**, а не берутся из `Content-Length`: заголовок
способен соврать, и скорость тогда получилась бы правдоподобной, но неверной.

**Прогрев.** Один запрос до начала отсчёта: первый запрос к хосту платит за
DNS, TCP и TLS, и без прогона первая выборка завышает и среднее, и разброс.

**Кеш обходим заголовками** `Cache-Control: no-cache, no-store`, а не
query-параметром: проверено, что `ash-speed.hetzner.com` отвечает на любой
query пустым ответом, а заголовки безобидны.

**Запросы строго последовательные.** Параллельные соединения мерили бы
суммарную ёмкость нескольких TCP-потоков — другая величина. Соединение
переиспользуется между запросами.

**Сжатие выключено** (`Accept-Encoding: identity`): сжатый ответ весил бы
заметно меньше файла, и скорость вышла бы завышенной.

**Ошибка не обрывает замер.** Таймаут или HTTP 5xx попадают в список неудачных и
в статистику не идут; видно «10 из 10» или «7 из 10», поэтому неполнота выборки
не спрятана.

## Адреса для замера

| Адрес | Размер | Когда брать |
|---|---|---|
| `https://ash-speed.hetzner.com/100MB.bin` | 100 МБ | дефолт, 10 запросов = 1 ГБ трафика |
| `https://ash-speed.hetzner.com/1GB.bin` | 1 ГБ | только при быстром канале: 10 ГБ трафика |
| любая «тяжёлая» картинка | — | на файлах меньше мегабайта время ответа забито RTT |

## Ограничения

- Только скачивание, скорость на отправку не измеряется.
- Один TCP-поток.
- Нужен файл побольше мегабайта, иначе измеряется в основном задержка.
